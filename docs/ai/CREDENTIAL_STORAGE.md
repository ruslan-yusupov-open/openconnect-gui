# Требования к безопасному запоминанию пароля

Это спецификация будущей работы, не описание уже реализованной защиты.

## Что уже есть

В `src/dialog/editdialog.ui` есть `batchModeBox` с пояснением о запоминании паролей. `StoredServer::load/save` читает и записывает пароль при batch, а `process_auth_form` в `src/vpninfo.cpp` умеет подставлять его в поле `password`. Успешный `main_loop` сохраняет профиль. Поэтому нужно проследить этот путь и исправить поведение, а не добавить второй независимый механизм.

По скриншоту нельзя установить причину повторного запроса: это может быть выключенная настройка, другое имя поля, ошибка расшифровки, отклонённый пароль или дополнительный фактор сервера. Диагностика должна различать эти случаи без записи значений секретов.

## Пользовательский сценарий

Пользователь явно включает сохранение обычного VPN-пароля для конкретного профиля. После успешной аутентификации пароль сохраняется с защитой ОС и используется при следующем Connect, включая перезапуск клиента. При отключённой опции подключение работает с вводом вручную. Ошибка хранилища объясняется пользователю; подключение с ручным вводом остаётся доступно.

Неверный сохранённый пароль вызывает повторный запрос с ограничением числа попыток; новый пароль заменяет запись после успешной аутентификации. Сетевая ошибка или ошибка сертификата не считается доказательством неправильного пароля. Отмена ввода ничего не перезаписывает. Отключение сохранения и удаление профиля удаляют секрет; ошибка удаления явно сообщается, успех не имитируется.

## Архитектурное решение к проработке

| Платформа | Предлагаемое направление | Поведение при недоступности |
| --- | --- | --- |
| Windows, первый целевой вариант | Системное хранилище Credentials либо DPAPI в контексте текущего пользователя; выбрать backend отдельным решением и проверить документацию API | Не записывать plaintext; показать ошибку и предложить ручной ввод |
| macOS | Keychain через отдельный backend | Те же требования; отсутствие backend не допускает открытого сохранения |
| Другие платформы | Хранение отключено до появления проверенного backend | Ручной ввод, понятное состояние опции |

Для DPAPI допустим защищённый blob в настройках; для системного хранилища — идентификатор записи. Base64, общий встроенный ключ и шифрование ключом, лежащим рядом с паролем, не удовлетворяют требованиям проекта. Не обещать защиту от вредоносного процесса, работающего с теми же полномочиями пользователя: границы выбранного backend нужно явно описать.

Идентификатор секрета должен однозначно учитывать профиль и учётную запись; при смене сервера, пользователя или протокола нельзя молча отправлять старый пароль новому адресату. Переименование профиля не должно терять доступ или оставлять бесхозную запись. Определить политику экспорта: секреты по умолчанию не экспортируются.

Миграция старых данных: прочитать старую запись, записать защищённую, проверить успех и только затем удалить старую. При сбое не заявлять успешную миграцию и не создавать новую открытую копию; предложить повторный ввод либо явное удаление старого секрета. Обработать повреждённый blob, несовпадение пользователя ОС, частичный сбой и повторный запуск миграции.

OTP-коды, PIN, токены сессии и обычный пароль не взаимозаменяемы. Не подставлять обычный пароль во все скрытые поля. Хранение OTP seed и приватного ключа — отдельная область R4; не включать их в новую функцию автоматически. Нельзя отключать MFA или проверку сертификата, чтобы добиться подключения без диалогов.

## Приёмочные проверки

1. Опция выключена: после перезапуска секрет не сохранён, ввод запрашивается.
2. Опция включена: успешное подключение, Disconnect/Connect и перезапуск не требуют повторного обычного пароля при совместимом ответе сервера.
3. Неверный пароль: ограниченный повторный запрос; отмена не затирает запись, успешный новый ввод обновляет её.
4. Недоступный/заблокированный backend и повреждённые данные: ошибка видна, plaintext не появляется, ручной ввод работает.
5. Отключение опции, удаление профиля и смена адресата: старый секрет удаляется либо не используется; ошибка удаления различима.
6. Миграция: успешный перенос удаляет старую запись; частичный сбой не теряет данные молча и допускает безопасный повтор.
7. Unicode и специальные символы проходят без изменения; секрет отсутствует в логах, экспорте и диагностике.
8. Обычный пароль не заменяет OTP/MFA; TLS-проверки сохраняются.

Для тестов использовать фиктивный backend и синтетические профили. Отдельные платформенные интеграционные тесты выполнять в тестовой учётной записи ОС; реальный VPN доступен только по отдельному разрешению.
