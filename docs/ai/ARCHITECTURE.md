## Основной поток данных

Главное окно выбирает StoredServer и запускает фоновую работу. `main_loop` вызывает `VpnInfo::connect()`. OpenConnect вызывает `process_auth_form`: доступный сохранённый пароль может заполнить поле `password`, иначе создаётся диалог ввода. После успешного подключения вызывается `StoredServer::save()`, затем VPN mainloop. Состояние возвращается в GUI через сигналы. Callback `progress_vfn` форматирует сообщения в буфер 512 байт и передаёт их Logger; FileLogger сохраняет сообщения на диск.

Связи владения и остановки в этом старом коде не следует считать образцовыми: `main_loop` удаляет VpnInfo, а worker продолжает обращаться к MainWindow. Перед изменением завершения нужно проследить ранние выходы, отмену диалогов и срок жизни каждого объекта. UI-операции должны выполняться в GUI-потоке. Нельзя исправлять проблему чужого mutex.unlock простой заменой на блокирующий вызов без проверки закрытия приложения и отмены.

## Точки расширения

Для паролей предполагается отдельный интерфейс хранилища с операциями чтения, записи и удаления, который используют профиль и аутентификация. `CredentialStore` — предлагаемая будущая сущность, сейчас такого класса нет. Его ошибки должны различаться: запись не найдена, хранилище недоступно, данные повреждены. UI показывает понятное состояние, а QSettings хранит несекретные метаданные или защищённый blob согласно выбранному backend.

Выделение контроллера соединения, построителя proxy URL и диспетчера диалогов допустимо отдельными задачами с поведенческими проверками. В учебном багфиксе не требуется переразбивать MainWindow, менять публичный API или формат профиля.

Не редактируй результаты AUTOUIC/AUTOMOC и `config.h`: их источники — `.ui`, заголовки QObject и `config.h.in`. Изменение зависимостей, схемы профиля, платформенной поддержки или владения объектами требует явного объяснения совместимости и отдельных проверок.
