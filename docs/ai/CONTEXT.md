# Контекст проекта

OpenConnect GUI — настольный VPN-клиент: пользователь создаёт профиль сервера, выбирает протокол и параметры аутентификации, нажимает Connect, вводит требуемые данные и наблюдает состояние соединения. GUI обращается к библиотеке OpenConnect; сетевой туннель не реализован самим интерфейсом.

Эта работа выполняется в [пользовательском форке](https://github.com/ruslan-yusupov-open/openconnect-gui), ветка назначения PR — `develop`. Исходная база: `1b9bc0ae61496a871dbee955ec2443e46d411ed4` от 18 января 2019 года. В `CMakeLists.txt` указана версия 1.5.3; в `CMake/Includes/ProjectDependencies.cmake` требуется Qt 5.11 или новее в пределах Qt 5; в `ProjectSettings.cmake` — C++17. Ревью предыдущего ДЗ относится к другой базе: [GitLab, f210cb5](https://gitlab.com/openconnect/openconnect-gui/-/commit/f210cb56fe561cd25b1b5bc12bf40c3966a03046). Номера строк и сведения о Qt 6 оттуда не применяются автоматически.

## Цель сопровождения

Сначала устранить подтверждённые дефекты безопасности и стабильности из [реестра](KNOWN_ISSUES.md). Затем довести существующее запоминание пароля до безопасного и понятного сценария: по желанию пользователя повторное подключение, в том числе после перезапуска, использует сохранённый обычный пароль. Политики сервера и запросы MFA сохраняют силу. Текущий учебный PR добавляет инструкции и один небольшой багфикс для проверки их применения; реализация защищённого хранилища — следующая работа.

## Сборка и запуск для новичка

Основная историческая платформа — Windows с Qt/MinGW; также есть ветки сборки для macOS и Unix. См. [требования исходного проекта](../sw_requirements.md) и [сборку](../dev_commandLine.md). Это исторические инструкции, а не подтверждение совместимости с современными ОС и пакетами.

Для Windows подготовь совместимый комплект Qt 5, MinGW, CMake и Git; для установщика нужен NSIS. В терминале с Qt и MinGW в PATH из корня репозитория:

```text
cmake -S . -B build-release -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build-release --parallel 2
```

При необходимости передай `-DCMAKE_PREFIX_PATH=<каталог установленного Qt 5>`. CMake может скачивать внешние зависимости; версии и источники смотри в `CMake/Includes/ProjectExternals.cmake` и `external/`. Не запускай целиком `contrib/build_mingw@win.cmd`: он содержит удаление каталога сборки и пути машины автора. Используй отдельные команды выше в новом каталоге.

Исполняемый файл ожидается в `build-release/bin/openconnect-gui.exe`; для запуска нужны библиотеки Qt/OpenConnect, platform plugin и рабочая настройка VPN-драйвера/vpnc-script. Установщик собирается отдельной командой `cmake --build build-release --target package` после успешной сборки и настройки упаковки. Не считай получение одного exe готовым установленным клиентом. Не используй настоящие профили или серверы для автоматических тестов.

Для macOS исходная конфигурация использует Qt 5, OpenConnect и GnuTLS, а также Security framework. Актуальные пути зависимостей нужно задать для своей машины. Команды установки из старой документации не являются проверенной современной инструкцией.

## Мини-глоссарий

| Термин | Значение в проекте |
| --- | --- |
| Профиль / StoredServer | Адрес сервера, протокол и параметры подключения, сохраняемые через QSettings |
| VpnInfo | Контекст OpenConnect и операции VPN-сессии |
| Batch mode | Существующая настройка автоматического заполнения, в UI связана с remember passwords |
| QSettings | Хранилище настроек; само по себе не обеспечивает защиту секретов |
| CryptData | Текущая обёртка кодирования/декодирования секретов с веткой Windows DPAPI |
| OTP / MFA | Одноразовый код / дополнительные факторы; не эквивалент обычному паролю |
| DPAPI | Системный механизм защиты данных Windows |

Новые документы и отчёт собраны в [REPORT.md](REPORT.md). Точка входа агента — [AGENTS.md](../../AGENTS.md).
