# Стиль и требования к изменениям

- C++17, Qt 5. Используй существующий `.clang-format`: четыре пробела, без табуляции, стиль скобок WebKit. Не форматируй весь старый файл ради небольшой правки. Не меняй стандарт C++ на основании поля `Standard: Cpp11` в конфигурации форматтера: стандарт сборки задаёт CMake.
- Сохраняй локальные соглашения именования и существующие английские строки UI; пользовательские строки создавай через принятый в окружении `tr()`/`QObject::tr()`. Новая документация и объяснения — на русском.
- Комментарий должен объяснять причину или контракт, если они неочевидны. Не добавляй учебные маркеры и шуточные суффиксы в рабочий код.
- Для ресурсов учитывай парный API освобождения; RAII применяй там, где он делает владение явным. Не заменяй библиотечный deleter обычным `free` или `delete`.
- Перед индексированием учитывай пустой ввод, перед преобразованием — длину и кодировку. Для callbacks сохрани ожидаемое поведение фильтрации, форматирования и усечения.
- Ошибки хранения секретов обрабатывай явно, без перехода к открытому тексту. Логи должны быть полезными без паролей, токенов, cookie и приватных ключей.
- Новую проверку размещай отдельно от production-кода; не подключай тяжёлый тестовый фреймворк для одного локального дефекта. Тест проверяет наблюдаемое поведение и должен отличать исходную ошибочную версию от исправленной.
- Не используй `assert` как единственную проверку в тесте, который может собираться с NDEBUG. При ошибке возвращай ненулевой код и понятное сообщение.
- В Markdown используй относительные ссылки внутри репозитория; не включай пути личной машины, настоящие адреса VPN или данные со скриншота пользователя. Ссылки на публичные исходники допустимы.
