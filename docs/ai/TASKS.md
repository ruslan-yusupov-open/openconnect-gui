# Типовые задачи и примеры промптов

Это шаблоны для будущих запусков. Реально использованные запросы находятся в [PROMPTS.md](PROMPTS.md).

## 1. Исправление дефекта callback журнала

**Промпт:**

> Строго следуй инструкциям проекта. Исправь R6: progress_vfn обращается к памяти перед буфером при пустом сообщении. Сохрани форматирование обычных сообщений, удаление одного завершающего перевода строки, усечение и фильтр TRACE. Добавь регрессионную проверку. Не меняй UI, зависимости и остальные замечания ревью.

**Ответ:** контекст и краткий план до правки; после — изменённые файлы, причина проверки длины, команды и статусы PASS/FAIL/NOT RUN.

**Готово:** пустой ввод не вызывает недопустимого доступа; обычный, длинный ввод и TRACE сохраняют поведение; исходная версия обнаруживается регрессией, исправленная проходит. Ограничения изолированной проверки явно названы.

## 2. Добавление безопасного сохранения пароля

**Промпт:**

> Строго следуй инструкциям проекта и CREDENTIAL_STORAGE.md. Проследи существующий Batch mode и реализуй безопасное сохранение обычного VPN-пароля для Windows. Выбери и обоснуй системный backend, исключи plaintext fallback, добавь удаление и миграцию. Сохрани ручной ввод и MFA. Остальные платформы не должны сохранять новые секреты открытым текстом. Не подключайся к настоящему VPN.

**Ответ:** текущий путь данных и решение backend, границы платформ, план; затем изменения UI/хранения, поведение ошибок, проверки и оставшиеся платформенные ограничения.

**Готово:** выполнены применимые пункты приёмки CREDENTIAL_STORAGE.md, тесты ошибок backend и миграции проходят; ограничения иных секретов R4 честно описаны. Наличие защищённого blob само по себе недостаточно без проверки использования и удаления.

## 3. Покрытие proxy тестами и исправление утечки

**Промпт:**

> Строго следуй инструкциям проекта. Для R3 и R5 проверь формирование proxy URL и безопасного сообщения журнала. Покрой HTTP, SOCKS5, IPv6 и специальные символы в логине/пароле тестами. Исправь выявленные ошибки, сохрани credentials только в строке для OpenConnect. Используй вымышленные данные и проверь все log sinks.

**Ответ:** граница между строкой подключения и диагностикой, небольшой план; изменения, набор входов и ожидаемых результатов, точные проверки.

**Готово:** библиотека получает корректно кодированный URL со схемой; ни один журнал не содержит пароль; тесты не используют реальный proxy; UI и чужие настройки не изменены.

## 4. Рефакторинг диалогов с сохранением сценариев

**Промпт:**

> Строго следуй инструкциям проекта. Устрани чужой mutex.unlock в R2 и дублирование синхронизации трёх диалогов. Сохрани тексты и результаты ввода. Проверь вызов из worker и GUI, cancel, закрытие главного окна и остановку потока. Не используй блокирующий вызов без анализа возможного deadlock.

**Ответ:** контракт потоков и владения, план отмены; затем схема изменённых связей, доказательства проверок и ограничения.

**Готово:** UI создаётся/используется в GUI-потоке, ожидание заканчивается при отмене и закрытии, срок жизни объектов определён; реальные тесты потоков выполнены, а не заменены статическим поиском mutex.
