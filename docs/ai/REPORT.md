# Отчёт: дополнение проекта инструкциями для ИИ

Дата: 6 сентября 2026 года. Проект — публичный форк OpenConnect GUI, C++17 / Qt 5, базовый коммит `1b9bc0ae61496a871dbee955ec2443e46d411ed4`. Изменения подготовлены для PR `docs/ai-instructions-ru` → `develop` в [форке пользователя](https://github.com/ruslan-yusupov-open/openconnect-gui).

## Инструмент и подключение инструкций

Выбран **OpenAI Codex**: подготовка в desktop-приложении, практическая проверка — отдельный запуск Codex CLI. До добавления правил изучена [официальная документация AGENTS.md](https://developers.openai.com/codex/guides/agents-md) (перенаправляется на ChatGPT Learn).

Codex при запуске собирает цепочку инструкций: глобальные правила, затем файлы от корня проекта до рабочего каталога. В каждом каталоге приоритет у `AGENTS.override.md`, затем `AGENTS.md`, затем настроенных fallback-имён; выбирается не более одного файла. Более близкие правила уточняют предыдущие. По умолчанию общий лимит — 32 KiB. Поэтому точка входа находится в корне Git, а подробные документы читаются по её явному указанию. Сами файлы `docs/ai/*.md` не заявлены автоматически подключаемыми правилами. После изменения инструкций нужна новая сессия для проверки обнаружения.

Практический запуск выполнен из корня `openconnect-gui`, не из родительского каталога `homework3`. В промпт не вставлялся текст AGENTS.md. Контрольная строка, порядок чтения контекста и формат результата наблюдались в новой сессии; это свидетельства применения, но не доказательство безошибочности агента на любых задачах.

## Практическая проверка инструкций

Задача агенту: исправить только R6 — чтение `buf[len - 1]` при `len == 0` в callback журнала, сохранив другие сценарии. Точный промпт приведён в [PROMPTS.md, пункт 3](PROMPTS.md#3-проверочный-запрос-агенту). Основной исполнитель подготовил стенд и проверил результат отдельно.

Команда запуска из корня проекта (PROMPT — точный текст пункта 3):

```text
codex exec --ephemeral --sandbox workspace-write --skip-git-repo-check --json -o <локальный-файл-ответа> <PROMPT>
```

Первый запуск не смог связаться с сервисом из сетевой песочницы и не выполнил правок. Повторный запуск получил доступ к сервису, сохранив режим workspace-write для действий агента. Он прочитал документы контекста и реестр, вывел `Контекст проекта: Qt 5 / C++17`, объяснил план и добавил единственную проверку:

```diff
-    if (buf[len - 1] == '\n')
+    if (len > 0 && buf[len - 1] == '\n')
```

За счёт короткого замыкания `&&` индексирование не выполняется при нулевой длине. Форматирование, размер буфера, удаление одного `\n`, TRACE и Logger не менялись. Агент не менял документы, UI, зависимости или архитектуру, не делал коммит и не подключался к VPN. В его ответе сборка и тесты обозначены NOT RUN, а не выдуманы. Извлечённые сообщения приведены в [VALIDATION.md](VALIDATION.md).

## Результаты проверки кода

Стенд извлекает функцию из production-файла, компилирует её с минимальным окружением и проверяет строки, переданные Logger. Проверка не заменяет интеграцию Qt/OpenConnect.

| Проверка | Результат |
| --- | --- |
| GCC 14.2 / AddressSanitizer, исходный callback | Ожидаемый FAIL на `empty` и `formatted_empty`: stack-buffer-overflow, READ of size 1 перед buf. Остальные 6 сценариев PASS |
| GCC 14.2 / AddressSanitizer, исправленный callback | PASS, 8 из 8 |
| MSVC 19.41 / ASan, исправленный callback | PASS, 8 из 8 |
| MSVC 19.41 / ASan, отрицательный контроль | Не обнаружил исходный дефект; этот прогон не засчитан доказательством регрессии |
| Документы | PASS: 12 Markdown-файлов, 34 относительные ссылки; UTF-8 читается без символов замены |
| Состав изменений и секреты | PASS: просмотр diff и новых файлов; реальный адрес VPN и скриншот не включены |
| Настройка полной сборки через MinGW Makefiles | FAIL: CMAKE_MAKE_PROGRAM и CMAKE_CXX_COMPILER не найдены |
| Полная сборка GUI и живое VPN-подключение | NOT RUN; нет полного MinGW/Qt toolchain, реальное подключение не требовалось |

Команды воспроизведения и ограничения — [README теста](../../tests/progress/README.md); фактические команды и сокращённая диагностика — [VALIDATION.md](VALIDATION.md). R6 исправлен и проверен изолированно, остальные R1–R5, R7–R8 остаются открыты. Безопасное хранение пароля в этом PR описано требованиями, ещё не реализовано.

## Трудности и выводы проверки

Главная содержательная трудность — разница кодовых баз; поэтому вместо копирования всего ревью составлена таблица применимости. Второй важный результат — обычного «тесты зелёные» недостаточно: MSVC/ASan пропустил дефект даже после отключения оптимизации. GCC/ASan дал нужный отрицательный контроль. Причина различия санитайзеров не установлена и не объясняется догадкой в качестве факта.

Сетевые ограничения первого запуска и доступ MSBuild к Windows SDK потребовали повторного запуска разрешённых команд вне внешней песочницы. Права пользователя и глобальная конфигурация Git не изменялись. Контрольная строка оказалась полезной проверкой формата, но основная оценка основана на diff, реальных командах и тестах.

Все использованные запросы перечислены в [«Использованных промптах»](PROMPTS.md). Следующая работа — исправления по приоритетам и реализация безопасного запоминания пароля по приёмочным сценариям.
