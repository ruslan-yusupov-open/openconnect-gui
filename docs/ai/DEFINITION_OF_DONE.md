# Критерии готовности

## Любое изменение

- Задача и критерии поведения определены; версия проекта проверена по коду.
- Diff ограничен задачей, чужие изменения сохранены, лицензия и архитектурные границы соблюдены.
- `git diff --check` не сообщает ошибок; просмотрен полный diff, включая новые файлы.
- Новые ссылки внутри репозитория разрешаются; документы не противоречат коду.
- Нет настоящих секретов, адресов пользовательской инфраструктуры, сборочных результатов и сырых журналов с личными данными.
- Ответ объясняет изменение, решение, точные проверки со статусами PASS/FAIL/NOT RUN и ограничения.

## Изменение кода

- Регрессионная проверка охватывает исходный дефект и соседние нормальные случаи; по возможности показано падение на исходном коде и успех после правки.
- Выполнена доступная сборка и необходимые тесты. Если полной среды нет, изолированная проверка допустима как ограниченное свидетельство; полная сборка явно отмечается NOT RUN или FAIL с причиной. Это не готовый релиз.
- Для изменения UI проверены ввод, отмена и закрытие; для worker — завершение и срок жизни; для хранения — ошибка backend, повторный запуск, удаление и миграция. Эти проверки обязательны для соответствующей задачи, а не для каждого Markdown PR.

## Учебный PR с инструкциями

- Есть контекст, архитектура, правила, минимум три сценария с промптами и критериями готовности.
- Механизм подключения Codex описан со ссылкой на официальную документацию.
- Агент применил правила к небольшой реальной модификации. В отчёте указаны промпт, фактический результат и свидетельства соблюдения; автоматическое обнаружение правил не приравнивается к ручному чтению.
- Список использованных промптов отделён от примеров для будущих задач.
- В PR приведены отчёт и пределы проверки; известные проблемы не названы исправленными без соответствующего diff.
